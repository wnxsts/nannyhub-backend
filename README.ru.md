# NannyHub · Бэкенд

[English](README.md) · [Фронтенд](https://github.com/wnxsts/nannyhub-frontend)

NannyHub помогает родителям и няням найти друг друга. Родители просматривают анкеты и ставят лайки, няни отвечают на понравившиеся предложения. Взаимный лайк создаёт совпадение и диалог.

Здесь находятся API на Spring Boot, авторизация, логика совпадений, хранение сообщений и миграции базы. Фронтенд на React запускается и публикуется отдельно.

## Что реализовано

- Регистрация родителей и нянь, хеширование паролей BCrypt и вход по JWT.
- Анкеты для двух ролей и получение текущего пользователя.
- Лента нянь, входящие лайки и взаимные совпадения.
- История и отправка сообщений через REST, подключение STOMP/SockJS.
- База PostgreSQL с миграциями Liquibase.

Это MVP без оплаты, бронирования и проверки личности. **Проверка доступа к чатам пока неполная:** REST-методы не проверяют участие пользователя в совпадении, а STOMP принимает ID отправителя от клиента. Текущую версию нельзя использовать для личной переписки в публичном общем экземпляре.

## Технологии

Java 21, Spring Boot 4.0.1, Spring Security, Spring Data JPA, PostgreSQL, Liquibase, Maven и JJWT. Есть интеграция OpenAPI; совместимость Swagger UI нужно проверять при обновлении Spring Boot или springdoc.

## Локальный запуск

Установите Java 21 и создайте в PostgreSQL базу `nanny_hub_db`. Maven Wrapper включён в проект.

```sh
cp .env.example .env
# Укажите в .env пароль базы и случайный JWT-ключ.
set -a
. ./.env
set +a
./mvnw spring-boot:run
```

Spring Boot сам не читает `.env`: команды выше экспортируют значения в окружение. Ключ можно создать командой `openssl rand -hex 32`. Не добавляйте `.env` в Git.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | JDBC-адрес; по умолчанию `jdbc:postgresql://localhost:5432/nanny_hub_db` |
| `DATABASE_USERNAME` | Пользователь БД; по умолчанию `postgres` |
| `DATABASE_PASSWORD` | Обязательный пароль БД |
| `JWT_SECRET` | Обязательный ключ подписи длиной не менее 32 байт |
| `ALLOWED_ORIGINS` | Точные адреса фронтенда через запятую; по умолчанию `http://localhost:5173` |
| `PORT` | HTTP-порт; по умолчанию `8080` |

При старте Liquibase применяет миграции, затем Hibernate проверяет схему.

```sh
./mvnw test                  # Нужна настроенная база PostgreSQL
./mvnw -DskipTests package   # Сборка JAR без запуска тестов
java -jar target/backend-0.0.1-SNAPSHOT.jar
```

## Основные маршруты

| Путь | Назначение |
| --- | --- |
| `/api/auth/**` | Регистрация и вход |
| `/api/me` | Текущий пользователь |
| `/api/parent/**`, `/api/nanny/**` | Анкеты |
| `/api/swipes/**` | Лента и лайки |
| `/api/matches/**` | Совпадения |
| `/api/chats/**` | Сообщения и история |
| `/ws` | Подключение SockJS/STOMP |
| `/actuator/health` | Проверка состояния |

Для защищённых HTTP-запросов нужен заголовок `Authorization: Bearer <token>`.

## Отдельный деплой

Dockerfile собирает приложение на Java 21 и запускает JAR от пользователя без root-прав:

```sh
docker build -t nannyhub-backend .
docker run --rm --env-file .env -p 8080:8080 nannyhub-backend
```

В контейнере `DATABASE_URL` должен указывать на доступный сервер БД, а не на собственный `localhost`. Подключите отдельную PostgreSQL, задайте секреты в настройках хостинга и используйте TLS-настройки провайдера. В `ALLOWED_ORIGINS` укажите точный HTTPS-адрес фронтенда. Для проверки состояния используйте `/actuator/health`, на обратном прокси разрешите WebSocket.

При сборке фронтенда его `VITE_API_URL` должен содержать HTTPS-адрес этого API. Аккаунт хостинга и работающий адрес деплоя пока не настроены. Перед публичным запуском нужно устранить указанное выше ограничение доступа к чатам.

## Структура

`controller` — маршруты API; `service` — логика приложения; `repository` и `entity` — работа с данными; `security` — JWT-авторизация. Миграции находятся в `src/main/resources/db/changelog`.
